# 知识库管理平台（项目实战 2.9）

> 一个「文档能进、权限能管、AI 能答、越权能拦、答完能沉淀」的企业知识库：
> 多格式解析切片 → 混合检索 → **四维数据权限服务端鉴权** → 流式问答与引用溯源 → FAQ 聚类沉淀与知识缺口闭环 → 运营看板。

- 交付形态：可运行前端控制台 + 后端业务与检索服务 + 向量化/大模型适配层 + 示例知识库数据集 + 端到端演示链路
- 技术栈：Python 3.10+（**仅标准库，零第三方依赖**）+ SQLite + 原生 ES Module 前端（无框架、无 CDN、离线可用）
- 向量化：默认本地哈希向量（零依赖），可一键切换 **BGE-M3**（OpenAI 兼容接口 / 本地模型），详见 [`docs/BGE-M3接入指南.md`](docs/BGE-M3接入指南.md)
- 开箱即跑：`python run.py` 自动建库、导入 30 篇示例制度文档并生成演示数据

## 三、核心设计

### 1. 四维数据权限：OR 语义 + 服务端单点鉴权

- 每个知识单元可配置 `global / department / role / user` 四类权限实体，**默认不公开**；
- 判定为**充分条件（OR）**：命中任意一类即可访问；
- **部门权限向上包含**：知识单元共享给「财务部」时，其子部门「财务部/结算组」成员亦可访问；
- **鉴权发生在“召回之后、拼 Prompt 之前”**：检索服务只负责召回，`permissions.split_candidates()` 负责裁剪，
  未放行的切片**绝不进入 Prompt**，因此不可能被大模型“说漏”；
- 权限变更立即失效鉴权缓存（版本号机制），无需重启。

```python
# app/rag.py —— 检索 → 鉴权 → 生成
retr = retrieve_and_authorize(ctx, question)   # allowed_ku / denied_ku / conf_allowed / conf_denied
if denial_dominant:                            # 最匹配的单元被拦截 → 只回能力范围内的提示
    yield DENY_MESSAGE.format(n=denied_count)
```

**越权提示只报数量、不报标题**（避免二次泄露）：

> 检测到相关知识文档，但您当前所属部门/角色无权查阅该内容。已为你检索到相关资料，其中 N 份文档因权限设置无法展示。

### 2. 检索链路

```
上传 → 解析（页码/段落/字符区间） → 切片（480 token，15% 重叠，标题路径入前缀）
     → 双通道召回：向量 Top-20（本地 512 维 signed-hashing / 可切 Embedding API）
                    + BM25 Top-10（自建倒排 + 中文二元组）
     → RRF 倒数排名融合 → 四维鉴权裁剪 → 置信度判定
     → Prompt 编排（带 [n] 引用编号） → SSE 流式输出 → 引用溯源卡片 → 审计与缺口落库
```

- 置信度 = `max(向量相似度, 查询词在命中切片的覆盖率)`，与向量引擎口径解耦；
- 置信度低于阈值（默认 0.34）或未命中 → 自动进入**知识缺口池**并按提问频次聚合；
- 命中最匹配单元但被拦截 → 输出权限缺失提示（不生成基于弱相关内容的“硬答”）。

### 3. 大模型适配层

| 模式 | 说明 |
| --- | --- |
| `local`（默认） | 本地抽取式引擎：完全基于检索片段生成“结论 / 关键要点 / 引用”，**不编造**，零依赖离线可用 |
| `openai` | OpenAI 兼容接口（DeepSeek / Qwen / vLLM / Ollama），逐帧解析 SSE，失败自动降级并提示 |

在 **组织与系统配置 → 模型与系统参数** 中填入 `Base URL`、`API Key`、`模型名` 即可切换真实大模型，
保存后立即生效；`API Key` 只落本地 SQLite，界面仅显示掩码（`sk-xxxx****abcd`）。

### 3. 向量化引擎：本地哈希 / BGE-M3 可插拔

| 模式 | 实现 | 维度 | 说明 |
| --- | --- | --- | --- |
| `local`（默认） | signed-hashing + 中文二元组 | 512 | 零依赖、离线、可复现；改述召回弱 |
| `openai` | OpenAI 兼容 `/embeddings` | 1024（BGE-M3） | 硅基流动 / 阿里百炼 / 智谱 / Ollama / TEI / vLLM |
| `sentence_transformers` | 本机加载 `BAAI/bge-m3` | 1024 | 无需服务进程，首次加载约 2.2GB 模型 |

- 对话与向量化**配置相互独立**（`embedding_base_url` / `embedding_api_key` / `embedding_model` / `embedding_dim`），可以「DeepSeek 生成 + BGE-M3 向量」；
- 切换模式后必须重建索引：`python scripts/reindex_embeddings.py`（页面会显示红色提示）；
- 阈值按引擎自动切换：本地 `0.60 / 0.72 / 0.34`，语义向量 `0.88 / 0.90 / 0.50`（`config.active_thresholds`）；
- 向量服务临时不可用时，问答自动退化为**纯关键词检索**并提示，不会混用不同向量空间的相似度。

> 完整接入步骤（三条路线、字段说明、验证方法、常见错误、成本估算、回滚）见
> [`docs/BGE-M3接入指南.md`](docs/BGE-M3接入指南.md)。

### 4. FAQ 沉淀与缓存

```
问答日志 → 按规范化问句去重聚合 → 单链连通分量聚类（并查集）
        → 频次 ≥ 5 → 生成候选 FAQ（关联知识单元 + 置信度）
        → 管理员审核编辑 → 发布 → 写入 FAQ 向量缓存
        → 新提问先过缓存（语义相似 + 词形相似取最大值）→ 命中即毫秒直出
```

> 阈值按向量引擎自动切换：本地哈希 **0.60 / 0.72 / 0.34**；BGE-M3 等语义向量 **0.88 / 0.90 / 0.50**。
> 语义档的缺口阈值经实测标定（相关问题检索置信度 0.59~0.75，无关问题约 0.41）。
> 如需固定值，可用 `KB_FAQ_THRESHOLD` / `KB_FAQ_CACHE_THRESHOLD` / `KB_GAP_THRESHOLD` 覆盖。

### 5. 看板指标口径

| 指标 | 口径 |
| --- | --- |
| PV | 问答请求次数 |
| UV | 去重用户数（按 `user_id`，不按 IP） |
| Token 消耗 | 输入 + 输出 token 之和 |
| 平均响应时长 | 首 token 时延与整段时延分开统计，取 P50 / P95 |
| FAQ 缓存命中率 | 缓存命中次数 / 总提问次数 |
| 知识覆盖率 | 有召回的提问数 / 总提问数 |

## 八、已知限制与扩展点

| 限制 | 说明 / 扩展方式 |
| --- | --- |
| 扫描件 PDF | 无文本层时返回明确提示；`app/parsers.py` 已预留 OCR 适配位（可接 PaddleOCR/Tesseract） |
| `.doc` 旧格式 | 不支持，提示另存为 `.docx` |
| 向量检索规模 | 进程内暴力检索，万级切片内表现良好；更大规模可替换为 pgvector / Milvus（`search.py` 单点替换） |
| 本地向量召回 | 本地哈希向量对**改述/同义**问法召回较弱，建议接入 BGE-M3（见接入指南）；切换后需重建索引 |
| 单机并发 | 标准库多线程 HTTP 服务，适合演示与小组使用；生产建议换 ASGI 部署 |
| 权限缓存 | 单进程内存缓存 + 版本号失效；多实例部署需改为 Redis 广播失效 |
