# BGE-M3 向量化接入指南

> 目标：对话继续用 DeepSeek（或任意大模型），**检索向量化换成 BGE-M3**，提升改述、同义问法的召回质量。
> 代码已内置三种向量模式，页面可切换，无需改代码；切换后需重建索引（一条命令）。

## 一、为什么是 BGE-M3

| 项目 | 本地哈希向量（默认） | BGE-M3 |
| --- | --- | --- |
| 维度 | 512 | 1024 |
| 语义能力 | 仅词形（中文二元组） | 多语言语义，支持改述、同义、跨语言 |
| 实测（本库 10 条评测） | 原句 Top1 5/5，改述 Top1 1/5 | 改述可正确召回 |
| 依赖 | 零依赖 | 需向量服务（API 或本地模型） |
| 成本 | 0 | 托管 API 有免费额度；本地模型约 2.2GB 磁盘 |

## 二、三条接入路线（任选其一）

### 路线 A：托管 API（推荐，5 分钟）

以硅基流动 SiliconFlow 为例（提供 `BAAI/bge-m3`，OpenAI 兼容，有免费额度）：

1. 注册并创建 API Key；
2. 页面「组织与系统配置 → 模型与系统参数 → 向量化（Embedding）」填写：

| 字段 | 值 |
| --- | --- |
| 向量模式 | OpenAI 兼容 `/embeddings`（BGE-M3 托管服务） |
| 向量服务地址 | `https://api.siliconflow.cn/v1` |
| 向量 Key | 你的 `sk-...` |
| 向量模型 | `BAAI/bge-m3` |
| 向量维度 | `1024` |

3. 点「保存配置」→ 点「**向量服务测试**」，应看到：`向量服务正常：BAAI/bge-m3，维度 1024，耗时 xxx ms`；
4. 重建索引（见第四节）。

> 其他兼容供应商同理：阿里百炼 `https://dashscope.aliyuncs.com/compatible-mode/v1`（模型 `text-embedding-v3`，1024 维）、
> 智谱 `https://open.bigmodel.cn/api/paas/v4`（`embedding-3`，2048 维）、自建 TEI / vLLM 服务。

### 路线 B：本地 Ollama（离线、免费）

```bash
# 1. 安装 Ollama 后拉取模型（约 1.2GB）
ollama pull bge-m3
# 2. 确认服务在 11434 端口
curl http://127.0.0.1:11434/v1/models
```

页面填写：

| 字段 | 值 |
| --- | --- |
| 向量模式 | OpenAI 兼容 `/embeddings` |
| 向量服务地址 | `http://127.0.0.1:11434/v1` |
| 向量 Key | 留空或任意填（Ollama 不校验） |
| 向量模型 | `bge-m3` |
| 向量维度 | `1024` |

### 路线 C：本机 sentence-transformers（无服务进程）

适合单机演示、不想装 Ollama：

```bash
pip install sentence-transformers          # 本机已有 torch，约 100MB 依赖
# 首次运行会自动下载 BAAI/bge-m3（约 2.2GB）到 ~/.cache/huggingface
```

页面填写：向量模式选「**本地加载 BGE-M3**」，向量模型 `BAAI/bge-m3`，维度 `1024`。
首次提问会慢一些（加载模型），之后单次编码约 50~150ms（CPU）。

## 三、配置字段说明

| 字段 | 说明 |
| --- | --- |
| `embedding_mode` | `local`（默认）/ `openai`（兼容接口）/ `sentence_transformers`（本地模型） |
| `embedding_base_url` | 向量服务地址；**留空则复用对话 Base URL**（DeepSeek 无 embeddings 接口，因此接 BGE-M3 时应显式填写） |
| `embedding_api_key` | 向量服务 Key；留空则复用对话 Key |
| `embedding_model` | 模型名（硅基流动需带组织前缀 `BAAI/bge-m3`） |
| `embedding_dim` | 维度校验值（BGE-M3 = 1024）；填写后维度不符会直接报错，避免脏索引 |
| `embedding_batch` | 批量重建时的批大小，默认 16 |

也可以不打开页面，直接用环境变量：

```bash
set KB_EMBEDDING_MODE=openai
set KB_EMBEDDING_BASE_URL=https://api.siliconflow.cn/v1
set KB_EMBEDDING_API_KEY=sk-xxxx
set KB_EMBEDDING_MODEL=BAAI/bge-m3
python run.py
```

## 四、切换后必须重建索引

```bash
python scripts/reindex_embeddings.py            # 重建全部切片 + FAQ 向量
python scripts/reindex_embeddings.py --dry-run  # 只探测服务与维度，不写库
python run.py --reindex                         # 等价快捷方式
```

预期输出：

```
  向量模式 : openai
  模型     : BAAI/bge-m3
  服务地址 : https://api.siliconflow.cn/v1
  期望维度 : 1024
  探测成功 : 维度 1024，耗时 180ms
  待重建   : 57 个切片，2 条 FAQ
  完成     : 57 个切片 + 2 条 FAQ，用时 3.2s
  索引签名 : openai:BAAI/bge-m3
```

> 不重建会怎样：库内是 512 维旧向量、查询是 1024 维新向量，相似度失真（检索变随机）。
> 为避免这种情况，切换后系统配置页会显示红色提示「向量模式已变更，请重建索引」。

## 五、阈值自动切换（无需手工改）

| 参数 | 本地哈希 | BGE-M3（语义） |
| --- | --- | --- |
| FAQ 聚类阈值 | 0.60 | **0.88** |
| FAQ 缓存阈值 | 0.72 | **0.90** |
| 知识缺口阈值 | 0.34 | **0.50** |

> 语义档阈值经实测标定（本库 66 条提问、9 条评测问题）：
> 同一问题簇内相似度 0.81~0.99，跨主题 0.32~0.64；相关问题检索置信度 0.59~0.75，无关问题约 0.41，
> 因此缺口阈值取 0.50（取 0.65 会把「水果烂了能赔吗」这类改述误判为缺口）。

代码按 `embedding_mode` 自动选择预设（`app/config.py::active_thresholds`），
若显式设置了 `KB_FAQ_THRESHOLD` 等环境变量，则以环境变量为准。

## 六、验证是否真的生效

1. **配置页**：`向量服务测试` 返回维度 1024、耗时正常；右侧参数区显示「向量化：BAAI/bge-m3（1024 维）」与 0.88/0.90/0.50；
2. **问答页**：回答正常、引用正常；右栏「最高置信度」会从 0.1~0.3 提升到 0.6~0.9；
3. **改述测试**（最能体现差别）：

| 提问（改述） | 本地哈希 Top1 | BGE-M3 预期 |
| --- | --- | --- |
| 住酒店一晚上最多能报多少钱 | ❌ 固定资产管理规范 | ✅ 差旅报销标准 |
| 收到的水果烂了能赔吗 | ❌ 员工手册 | ✅ 退换货与售后政策 |
| 刚入职要交什么资料 | ✅（Top3） | ✅ 更稳定命中入职指引 |

4. **日志**：`data/kb.sqlite3` 的 `query_logs.top1_sim` 会整体上移；`kv.embedding_signature` 应为 `openai:BAAI/bge-m3`。

## 七、常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `HTTP 401 / 403` | Key 错误或无权限 | 检查 Key，注意不要带引号/空格 |
| `HTTP 404` | 地址少了 `/v1`，或模型名写错 | 地址形如 `https://api.siliconflow.cn/v1`；模型 `BAAI/bge-m3` |
| `维度不符：期望 1024，实际 1536` | 维度填错或模型不是 BGE-M3 | 改 `embedding_dim`，或换模型 |
| 连接超时 | 网络/代理 | 检查代理；Ollama 场景确认 11434 端口 |
| 提问时提示「向量服务暂不可用，本次退化为关键词检索」 | 问答时服务临时不可用 | 服务恢复后无需重启；回答仍可用，但召回质量下降 |
| 重建索引中途失败 | 网络抖动 | 重新执行；脚本为覆盖写，可重复运行 |

## 八、成本参考

本示例库 57 个切片 + 2 条 FAQ ≈ 1.2 万 token。托管 API 一次性重建通常**不到 1 分钱**；
日常提问每条只编码问题本身（约 20 token），可忽略。

## 九、回滚

页面把「向量模式」改回「本地哈希向量」→ 保存 → 再执行一次 `python scripts/reindex_embeddings.py`，
即可回到零依赖状态（索引签名变回 `local:hash512`）。

## 十、本库实测结果（2026-11-13）

**评测集**：9 条改述问题（正确文档已知） + 1 条与知识库无关的问题；指标 = Top1 / Top3 是否命中正确文档。

| # | 提问（改述） | 正确文档 | 本地哈希 Top1 | BGE-M3 Top1 |
| :--: | --- | --- | --- | --- |
| 1 | 住酒店一晚上最多能报多少钱 | 差旅报销标准 | ❌ 固定资产管理规范 | ✅ 差旅报销标准 |
| 2 | 没休完的假期能不能留到明年 | 员工手册 | ✅ | ✅ |
| 3 | 发票开错了怎么处理 | 发票开具与查验规范 | ✅ | ✅ |
| 4 | 刚入职要交什么资料 | 新员工入职指引 | ✅ | ✅ |
| 5 | 收到的水果烂了能赔吗 | 退换货与售后政策 | ❌（Top3 命中） | ✅（Top1 为物流时效，Top3 命中） |
| 6 | 出差住宿超标了自己贴钱吗 | 差旅报销标准 | ✅ | ✅ |
| 7 | 客户投诉特别严重怎么升级 | 客户投诉分级与响应标准 | ✅ | ✅ |
| 8 | 离职后账号多久注销 | 账号与权限管理规范 | ✅ | ✅ |
| 9 | 生鲜坏了退款多久到账 | 退换货与售后政策 | ✅ | ✅ |
| — | 公司附近哪家餐厅好吃（无关） | — | 置信度 0.111 | 置信度 0.411 |

| 指标 | 本地哈希（512 维） | BGE-M3（1024 维） |
| --- | --- | --- |
| Top1 命中率 | 7/9 | **8/9** |
| Top3 命中率 | 8/9 | **9/9** |
| 相关问题最高置信度区间 | 0.07 ~ 0.38 | **0.59 ~ 0.75** |
| 无关问题置信度 | 0.11 | 0.41（低于缺口阈值 0.50，正确判为缺口） |
| 同簇问法相似度（50 条生鲜问法） | 需阈值降到 0.60 才能聚合 | **0.81 ~ 0.99，用 0.88 即可聚合** |
| 57 切片 + 2 FAQ 重建耗时 | 0.06 秒（本地计算） | 7.2 秒（4 次 API 调用） |
| 单次提问额外耗时 | 0 毫秒 | 约 200~600 毫秒 |

> 首次调用 SiliconFlow 有冷启动（实测 62.8 秒），之后稳定在百毫秒级；重建索引可重复执行。

**结论**：BGE-M3 把改述问题的 Top1 命中从 7/9 提升到 8/9、Top3 从 8/9 提升到 9/9，
置信度整体从 0.1~0.3 抬到 0.6~0.75，同时无关问题仍能被正确判为缺口——这正是更换向量引擎的价值。
