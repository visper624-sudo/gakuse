### 1.3 技术选型与理由

| 选型 | 理由 | 代价 |
| --- | --- | --- |
| Python 标准库 HTTP 服务 | 零依赖、双击即跑、答辩环境无风险 | 并发能力有限，不适合生产 |
| SQLite + WAL | 单文件、事务安全、无需部署数据库 | 写并发弱；多实例需换 PG |
| 自研倒排 + 二元组 | 中文无需 jieba，避免额外依赖 | 语义弱于专业分词器 |
| 本地哈希向量为默认 | 离线可演示、零成本、可复现 | 改述召回差（实测 Top1 7/9） |
| BGE-M3 可插拔 | 质量高、中文强、有托管 API | 需网络/Key，切换后必须重建索引 |
| 原生 JS + 自研 SVG 图表 | 无构建、无 CDN、断网可用 | 图表能力弱于 ECharts |
| 前端三栏工作台 | 与「检索与鉴权轨迹」联动，直观体现鉴权 | 小屏需适配 |

```
           cache_hit, token_in, token_out, first_token_ms, total_ms, answered, created_at)
audit_logs(id, user_id, username, action, target, detail, ip, created_at)
```

**设计要点**

- `chunks.vec` 存 BLOB（`struct.pack` 的 float32），避免把向量放进 JSON 反复序列化；
- `chunk_terms` 是「自建倒排表」，BM25 直接 SQL 取 postings，不依赖 FTS5（FTS5 对中文分词不友好）；
- `ku_perms` 用 `(ku_id, perm_type, principal_id)` 联合主键，天然去重；
- `query_logs.denied_ids` 记录**被拦截的 ku_id**，用于审计与「越权拦截次数」指标。

| 3 | 鉴权问答 | 输入问题 | 流式回答 | `api.chat_stream` → `rag.answer_stream` |
| 4 | 沉淀 | 点「立即挖掘」 | FAQ 上线 | `faq.mine` → 审核 → `publish_candidate` → 缓存 |
| 5 | 缺口闭环 | 未命中提问 | 补充任务 | `rag.record_gap` → `faq.gap_to_task` |

### 2.2 一次提问的完整时序（带调用栈）

```
① 前端：fetch POST /api/chat/stream {session_id, question}
        ↓ （ReadableStream 逐帧解析 event:/data:）
② server._handle → api.dispatch
   ├─ 路由匹配：POST /api/chat/stream，perm="ai:chat"
   ├─ 统一鉴权：_require(req,"ai:chat")  ← 未登录 401 / 无权限 403
   └─ 处理器返回 StreamResponse(gen)
        ↓
③ rag.answer_stream(ctx, session_id, question)  【生成器，逐事件 yield】
   ├─ 取最近 6 条历史（多轮上下文）
   ├─ 建/复用会话；写入 user 消息
   ├─ yield ack{session_id}
   ├─ 【缓存】faq_cache_lookup：与已发布 FAQ 比 max(余弦, 词形 Jaccard) ≥ 0.90
   │     命中 → 直接流式回标准答案 + done(cache_hit=true)，结束
   ├─ 【召回】search.hybrid_search
   │     ├─ _vector：查询向量化（strict）→ 全量切片余弦 → Top20
   │     ├─ _bm25：二元组查询 → 倒排 postings → BM25 → Top10
   │     └─ RRF：score = Σ 1/(60+rank) → 取 Top20 候选切片
   ├─ 【鉴权】permissions.split_candidates(ctx, 候选 ku_id 列表)
   │     ├─ visible_ku_ids：SQL 取 global/user/department/role 命中集合
   │     ├─ allowed_ku / denied_ku（保持入队顺序）
   │     └─ 计算 conf_allowed / conf_denied（向量 or 覆盖率）
   ├─ yield trace{retrieved, allowed/denied 单元数, 候选明细, 置信度}
   ├─ 分支判定（顺序不可颠倒）：
   │     ① 无权优先：conf_denied ≥ max(conf_allowed, gap) → 只回权限提示
   │     ② 缺口：无可用切片 或 conf_allowed < gap → 回「未命中」并落缺口池
   │     ③ 正常：拼 Prompt → 生成 → 引用 → 落库
   ├─ 【生成】DeepSeek 流式（失败自动降级本地抽取式）
   ├─ yield delta{text} × N
   ├─ yield citations{items}（只保留答案真正用到的切片）
   ├─ 【落库】messages + query_logs（token/时延/召回/拦截）
   └─ yield done{latency_ms, usage, cache_hit}
        ↓
④ 前端渲染：气泡 + 引用卡片 + 右栏轨迹
```

## 三、分阶段详解

> 每个阶段统一结构：**做什么 → 代码 → 知识点 → 易错点**

### 阶段 1 · 启动与初始化

**做什么**
1. 建目录（data/uploads/cache）、生成 JWT 密钥（`secret.key`，重启不失效）；
2. `executescript` 建全部表（`CREATE TABLE IF NOT EXISTS`，幂等）；
3. 首次启动灌演示数据；写入向量口径签名；
4. 起 HTTP 服务。

**代码**：`app/config.py`（`_load_secret`）、`app/db.py::init_db`、`app/seed.py::run`

```python
# config.py —— 签名密钥落盘，避免重启后登录态全部失效
def _load_secret() -> str:
    p = DATA_DIR / "secret.key"
    if p.exists():
        return p.read_text(encoding="utf-8").strip()
    s = secrets.token_hex(32)
    p.write_text(s, encoding="utf-8")
    return s
```

**知识点**
- 建表语句必须幂等（`IF NOT EXISTS`），否则每次启动都报错；
- 密钥、DB、上传目录与代码分离（`data/` 可删除重建）；
- SQLite 开 WAL：读写不互相阻塞。

**易错点**
- ❌ 密钥写在代码里 → 换机/换人泄露；✅ 落盘 + 可被环境变量覆盖；
- ❌ 首次启动同步下载大模型 → 启动超时；✅ 启动只建库，模型/索引操作单独触发。

### 阶段 2 · 登录与身份上下文

**做什么**
1. PBKDF2-SHA256（120,000 轮 + 随机盐）校验密码；
2. 签发 HMAC-SHA256 JWT（含 `sub`、`exp`，默认 12 小时）；
3. 组装用户上下文：部门、**部门祖先闭包**、角色集合、功能权限集合。

**代码**：`app/util.py`（`hash_password/jwt_encode/jwt_decode`）、`app/permissions.py::build_ctx`

```python
# permissions.py —— 部门闭包：自己 + 所有上级部门
def dept_ancestors(dept_id: int | None) -> list[int]:
    out, cur, guard = [], dept_id, 0
    while cur and guard < 20:              # guard 防止脏数据造成死循环
        out.append(cur)
        row = db.query_one("SELECT parent_id FROM depts WHERE id=?", (cur,))
        if not row:
            break
        cur, guard = row["parent_id"], guard + 1
    return out
```

**知识点**
- 密码不能「哈希一次」：必须加盐 + 慢哈希（PBKDF2/bcrypt/argon2）；
- JWT 是无状态的：服务端无法主动踢人，只能靠短期过期 + 黑名单；
- 身份上下文必须**一次查全**（角色/部门/权限），否则每步鉴权都查库。

**易错点**
- ❌ 用 `md5(password)` → 彩虹表秒破；✅ PBKDF2 + 盐；
- ❌ 把角色/部门信息交给前端后信任前端回传 → 直接伪造；✅ 上下文永远从 Token 里的 uid 重查数据库；
- ❌ `?token=` 查询参数在生产开启 → 日志/Referer 泄露；✅ 本项目仅用于演示/截图，生产应关闭。

### 阶段 3 · 文档解析

**做什么**：把 4 种格式统一转成「段落块」列表：`Block(text, heading_path, page_no, para_index, char_start, char_end)`。

| 格式 | 方案 | 页码来源 |
| --- | --- | --- |
| TXT | 空行分段 + 「第X章/一、」标题识别 | 按 1400 字符估算 |
| Markdown | `#` 标题栈 → 标题路径 | 按 1400 字符估算 |
| DOCX | `zipfile` 解 `word/document.xml` + ElementTree，读 `w:pStyle` 判断标题，读 `w:tbl` 表格 | 按 1200 字符估算 |
| PDF | **自研解析器**：对象扫描 → 页树 → 字体 ToUnicode → 内容流算子 | 真实页序 |

**代码**：`app/parsers.py::parse_text / parse_docx / parse_pdf`

```python
# parsers.py —— PDF 对象边界扫描（关键：不能在 8KB 里盲找 stream）
@staticmethod
def _object_bounds(data: bytes, start: int) -> tuple[int, int, int]:
    i, n, depth = start, len(data), 0
    while i < n:
        c = data[i]
        if c == 0x28:                       # '(' 字面字符串：跳过，避免误判
            i += 1
            while i < n:
                if data[i] == 0x5C: i += 2; continue
                if data[i] == 0x29: i += 1; break
                i += 1
            continue
        if c == 0x3C and data[i + 1] == 0x3C: depth += 1; i += 2; continue
        if c == 0x3E and data[i + 1] == 0x3E: depth -= 1; i += 2; continue
        if c in (0x5B, 0x5D):
            depth += 1 if c == 0x5B else -1; i += 1; continue
        if depth <= 0 and data[i:i + 6] == b"stream":   # 只有字典闭合后才是真 stream
            ...
        if depth <= 0 and data[i:i + 6] == b"endobj":
            return i, 0, 0
        i += 1
```

```python
# parsers.py —— 中文 PDF 的核心：ToUnicode CMap
def _parse_cmap(self, data: bytes) -> dict[int, str]:
    mapping = {}
    for block in re.findall(rb"beginbfchar(.*?)endbfchar", data, re.S):
        for src, dst in re.findall(rb"<([0-9A-Fa-f]+)>\s*<([0-9A-Fa-f]+)>", block):
            mapping[int(src, 16)] = self._hex_to_bytes(dst).decode("utf-16-be", "ignore")
    ...
```

**知识点**
- PDF 文本不是明文：`Identity-H` 编码下内容流里是 **字形编号**，必须查 `ToUnicode` 才能还原文字；
- PDF 1.5+ 有**对象流（ObjStm）**压缩：对象藏在压缩流里，要先解压再扫描；
- DOCX 是 zip，`python-docx` 只是封装，标准库 `zipfile + ElementTree` 完全够用；
- 页码/段落/字符区间是「引用溯源」的根，解析阶段丢了，后面补不回来。

**易错点**
- ❌ 用正则 `re.search(r'/Type\s*/Page')` 全局扫 → 把跨对象的内容误当一个对象（本项目最初就踩了：对象 2 的 dict 吞掉了下一个对象，`/Kids` 误判导致页树为空）；
- ❌ 只读 `Tj` 不读 `TJ` → 大量文本丢失；✅ `Tj`、`TJ`、`'`、`"` 都处理；
- ❌ 不处理 `Td/Tm/T*` 换行 → 全篇一行，切片失效；
- ❌ 扫描件当文本 PDF → 抽出 0 字；✅ 明确报错「需 OCR 适配器」；
- ❌ DOCX 只取 `w:t` → 表格内容全丢；✅ 单独处理 `w:tbl`；
- ❌ 按行当段落 → 一条制度被切成 20 个碎片；✅ 按句末标点合并折行。

### 阶段 4 · 切片（Chunking）

**做什么**：把段落块打包成约 480 token 的切片，重叠 15%（约 72 字），标题路径拼进切片前缀。

**代码**：`app/chunker.py::chunk_doc`

```python
def flush():
    body = "\n".join(p["text"] for p in cur).strip()
    head = cur[0]["heading_path"] or ""
    prefix = f"《{head}》\n" if head else ""          # 标题路径进正文，提升召回
    chunks.append({...})                              # 页码/段落/字符区间取自首块与尾块
    # 生成重叠：从尾部回退不超过 overlap_chars 的若干块
    tail, tail_len = [], 0
    for p in reversed(cur):
        if tail_len + len(p["text"]) > overlap_chars and tail:
            break
        tail.insert(0, p); tail_len += len(p["text"])
    cur, cur_len = tail, tail_len
```

**知识点**
- 中文 1 字 ≈ 1 token，英文 1 词 ≈ 1 token → 无需 tiktoken 也能估算；
- 重叠解决「一句话被切断」导致的条件丢失；
- 标题路径前缀（`《差旅报销标准》 > 第二章 住宿标准`）能显著提升短问句召回；
- 切片元数据（page/para/char_start/char_end）必须**单调递增且连续**，否则引用跳转错位。

**易错点**
- ❌ 切片按固定字符硬切 → 句子断裂；✅ 按段落 + 句末标点；
- ❌ 重叠实现成「复制上一片」→ 重复内容污染索引；✅ 只回退尾部若干块，并用正文前 120 字去重；
- ❌ 切片过大（>1000 token）→ 一片多主题，向量被平均化；
- ❌ 切片过小（<100）→ 上下文缺失，答案碎片化；
- ❌ 忘记记录 `char_start/char_end` → 引用卡片无法定位原文。

### 阶段 5 · 向量化

**做什么**：把切片文本编码成归一化向量，写入 `chunks.vec`。三种引擎：

| 模式 | 实现 | 维度 | 适用 |
| --- | --- | --- | --- |
| `local` | signed hashing（中文二元组 + 拉丁词） | 512 | 离线、零依赖 |
| `openai` | POST `{base}/embeddings`（BGE-M3 等） | 1024 | 硅基流动/百炼/Ollama/TEI |
| `sentence_transformers` | 本机加载 `BAAI/bge-m3` | 1024 | 单机、无服务进程 |

**代码**：`app/embed.py::embed_texts`

```python
def embed_texts(texts, cfg=None, strict=False):
    mode = cfg.get("embedding_mode") or "local"
    if mode == "local":
        return [embed_local(t) for t in texts]
    try:
        if mode == "sentence_transformers":
            out = _st_embed(texts, cfg.get("embedding_model"))
        else:
            out = []
            for i in range(0, len(texts), batch):      # 批量请求，控制 QPS
                out.extend(_post_embeddings(texts[i:i + batch], cfg))
    except EmbeddingError:
        if strict:
            raise                                  # 建索引必须失败，不能写脏数据
        return [embed_local(t) for t in texts]     # 问答链路降级
    if dim and out and len(out[0]) != dim:
        raise EmbeddingError(f"向量维度不符：期望 {dim}，实际 {len(out[0])}")
    return out
```

**知识点**
- 向量必须 **L2 归一化**，余弦相似度才等价于点积；
- 维度必须与库内一致，否则 `cosine` 会按短的一方静默截断 → 相似度失真；
- 批量（batch=16）比逐条快数倍，也更容易触发限流，需要重试与快速失败；
- `strict` 语义：**建索引严格、问答可降级**。

**易错点**
- ❌ 把 `embedding_base_url` 留空 → 复用对话 `base_url`（DeepSeek 没有 `/embeddings`）→ 404；
- ❌ 模型名写 `bge-m3`（缺组织前缀）→ 硅基流动 404；✅ `BAAI/bge-m3`；
- ❌ 维度填 512（旧本地口径）→ 报维度不符；
- ❌ 服务挂了仍静默降级写库 → 512/1024 混存，相似度乱套；✅ 建索引 `strict=True`；
- ❌ 首次调用超时（冷启动实测 62.8s）→ 把超时设成 10s 必挂；✅ 默认 60s。

**做什么**：写 `knowledge_units` → 逐片写 `chunks` + `chunk_terms` + 向量 → 设置默认权限 → 失效进程内向量索引。

**代码**：`app/ingest.py::process_file / _insert_chunks`


- ❌ 文件名直接拼路径 → 路径穿越；✅ `safe_name()` + UUID 前缀。

### 阶段 7 · 混合检索

**做什么**：向量 Top20 + BM25 Top10 → RRF 融合 → 返回带元数据的候选切片。

**代码**：`app/search.py::_bm25 / _vector / hybrid_search`

```python
# BM25：k1=1.5, b=0.75，idf 用标准公式
idf = math.log(1 + (n_docs - df + 0.5) / (df + 0.5))
denom = tf + k1 * (1 - b + b * dl / avgdl)
scores[cid] += idf * (tf * (k1 + 1)) / denom

# RRF：只用名次，不用原始分（向量 0~1 与 BM25 0~无上限，量纲不同）
rrf[cid] += 1.0 / (RRF_K + rank)     # RRF_K = 60
```

**知识点**
- 中文关键词检索不能按空格分词：本项目用**中文二元组**（`差旅` `旅住` `住宿`…）+ 拉丁词；
- BM25 的 `idf` 需要 `df`（含该词的切片数），所以倒排表要能按 term 反查；
- RRF 的价值：**免调权重**地把两路不同量纲的结果融合；
- 检索结果要带 `channels`（vector/keyword/both），前端才能展示「为什么召回」。

**易错点**
- ❌ 直接把向量分和 BM25 分相加 → BM25 分远大于 1，完全压制向量；
- ❌ 用 FTS5 默认分词做中文 → 一整句被当一个 token，几乎搜不到；
- ❌ 候选只取向量 Top5 → 关键词召回的好结果进不来；
- ❌ 召回后不重新按 `ku_id` 去重 → 同一文档占满上下文。

### 阶段 8 · 四维鉴权（本项目核心）

**做什么**：召回之后、拼 Prompt 之前，按 `global / department / role / user` 四类实体做 **OR** 判定；未授权的切片绝不进入 Prompt。

**代码**：`app/permissions.py::visible_ku_ids / split_candidates`、`app/rag.py::retrieve_and_authorize`

```python
rows = db.query(
    """SELECT ku_id FROM ku_perms WHERE perm_type='global'
       UNION
       SELECT ku_id FROM ku_perms WHERE perm_type='user' AND principal_id=?""", (str(uid),))
visible = {r["ku_id"] for r in rows}
# 部门：principal_id ∈ 我的部门祖先闭包（共享给上级部门 → 子部门可见）
# 角色：principal_id ∈ 我的角色集合
...
def split_candidates(ctx, candidate_ids):
    visible = visible_ku_ids(ctx)
    allowed, denied = [], []
    for cid in candidate_ids:                  # 保持召回顺序
        (allowed if cid in visible else denied).append(cid)
    return allowed, denied
```

**知识点**
- 「默认拒绝」：`ku_perms` 没有任何记录 → 谁都不能访问（连创建者都靠初始个人授权）；
- 部门权限是**向上包含**：共享给「财务部」，其子部门「财务部/结算组」成员可见；
- 鉴权位置决定安全：**召回后、Prompt 前**，模型看到的只有已授权内容；
- 缓存失效：权限写入后 `bump_version()` 清空 `_vis_cache` / `_ku_cache`。

**易错点**
- ❌ 在 SQL 召回阶段就 `JOIN` 权限过滤 → 会导致「召回数量不足」，且难以统计拦截数；
- ❌ 前端过滤 / 答案出来后再打码 → 模型已经看过内容，等于没防；
- ❌ 提示里写「《高管薪酬细则》无权限」→ **二次泄露**；✅ 只报数量：「其中 N 份文档因权限设置无法展示」；
- ❌ 部门匹配只用 `dept_id` 相等 → 共享给上级部门时子部门看不到；
- ❌ 缓存不失效 → 改了权限还能看到旧内容；
- ❌ 只保护问答接口，台账接口漏鉴权 → 猜 ID 直接读全文（**本项目开发中就踩过**：路由表里配了 `perm` 但分发器没有执行，已修复为 **dispatch 统一执行路由级权限**，并新增测试 `test_07b` 覆盖）。

### 阶段 12 · FAQ 沉淀

**做什么**：历史提问 → 规范化去重 → 聚类（同义合并）→ 频次 ≥5 生成候选 → 人工审核 → 发布 → 写缓存向量 → 新提问先查缓存。

**代码**：`app/faq.py::mine / publish_candidate`、`app/rag.py::faq_cache_lookup`

```python
# 并查集做「单链连通分量」：结果与遍历顺序无关（贪心聚类会因顺序不同而分裂）
for i in range(n):
    for j in range(i + 1, n):
        if combined_sim(items[i]["vec"], items[i]["terms"],
                        items[j]["vec"], items[j]["terms"]) >= threshold:
            union(i, j)
```

```python
# 缓存匹配：max(语义余弦, 词形 Jaccard)，阈值随向量引擎切换（本地 0.72 / 语义 0.90）
sim = max(embed.cosine(qv, embed.unpack(r["vec"])), jaccard(qterms, terms_of(r["question"])))
if sim < llm.thresholds()["cache"]:
    return None, []
```

**知识点**
- 先按 `normalize_query`（去标点/去空格/小写）去重，再做 O(n²) 聚类，n 从 237 降到 66；
- 聚类用**连通分量**而非贪心，避免「同簇被拆成两个候选」；
- 候选 FAQ 的答案也是「检索 + 生成」，不是空模板；
- 发布后必须把 FAQ 向量写入，否则缓存永远不命中。

**易错点**
- ❌ 直接对全部日志两两比较 → 240 条变 2.8 万次比较，慢且无意义；
- ❌ 阈值用 0.88 却在本地哈希向量上跑 → 只有原句能合并，同义问法全分散；
- ❌ 发布只写数据库不写缓存向量 → 命中率 0；
- ❌ 审核发布后不刷新前端列表 → 用户以为没生效。

- 切换向量引擎后**必须**重建，否则查询向量与库内向量不在同一空间；
- 签名（`local:hash512` / `openai:BAAI/bge-m3`）用于提示「索引待重建」；
- 重建失败要能重跑：覆盖写，天然幂等；
- 阈值随引擎自动切换（`config.active_thresholds`），无需手工改。

**易错点**
- ❌ 改了 `chunk_size` 只重建向量 → 切片没重切，参数不生效；✅ `run.py --reset` 或重解析；
- ❌ 只重建 `chunks` 忘了 `faqs` → FAQ 缓存相似度错乱；
- ❌ 重建期间继续问答 → 部分切片新向量、部分旧向量；✅ 演示时先停问答或接受短暂降级。

### 阶段 15 · 功能权限与前端渲染

**做什么**：菜单权限决定左侧导航是否出现；操作权限决定按钮/接口是否可用；数据权限决定能看哪些知识。

**代码**：`app/permissions.py::PERM_CATALOG`、`api.dispatch`、前端 `app.js::allowedRoutes`

```python
# 统一在分发处执行路由级权限，处理器内部只做登录校验或额外细粒度判断
if perm:
    _require(req, perm)
return fn(req)
```

**知识点**
- 权限分两层：**功能权限**（菜单/按钮/接口）+ **数据权限**（知识单元可见性）；
- 前端隐藏按钮只是体验，接口必须再校验一次（本项目 `dispatch` 统一拦截）；
- 角色权限变更后，前端要重新拉 `/api/auth/me` 才能看到新菜单。

**易错点**
- ❌ 只在前端隐藏菜单，接口不校验 → 直接调 API 绕过；
- ❌ 路由表里写了 `perm` 但分发器没执行 → 「配置了却没用」（本项目真实踩过并修复）；
- ❌ 把「知识管理员」和「系统管理员」合并成一个角色 → 权限过大，无法演示最小权限。

## 四、核心代码专题

### 4.1 鉴权：`visible_ku_ids` 为什么不用 JOIN 召回？

```python
def visible_ku_ids(ctx):
    rows = db.query("""SELECT ku_id FROM ku_perms WHERE perm_type='global'
                       UNION
                       SELECT ku_id FROM ku_perms WHERE perm_type='user' AND principal_id=?""",
                    (str(uid),))
    visible = {r["ku_id"] for r in rows}
    for r in db.query("... perm_type='department' AND principal_id IN (...)", depts): ...
    for r in db.query("... perm_type='role' AND principal_id IN (...)", roles): ...
    return visible
```

- **先召回、后过滤**：可以统计「召回但被拦截」的数量（`denied_ku`），这是需求 2.9.4 明确要求的能力；
- 如果把权限写进召回 SQL：`WHERE ku_id IN (subquery)`，虽然也安全，但拿不到被拦截清单，也难做「部分资料受限」的提示；
- 缓存粒度是 **用户**，`bump_version()` 一次性清空，代价可接受（30 篇文档量级）。

### 4.2 RAG 主状态机的分支顺序

```python
① 缓存命中          → 直接回标准答案（0 次 LLM 调用）
② 无权优先          → conf_denied ≥ max(conf_allowed, gap) 时只回权限提示
③ 缺口              → 无可用切片 或 conf_allowed < gap 时回「未命中」并落缺口
④ 正常生成          → 拼 Prompt → 流式 → 引用 → 日志
```

**顺序不能颠倒**：

- 若先判缺口再判无权：`conf_allowed` 低但 `conf_denied` 高时，会回「没有资料」——**该说权限受限**，用户会去重复提问；
- 若先判缓存再判权限：FAQ 缓存也可能指向受限文档，所以缓存命中后还要校验关联 `ku` 是否可见（`faq_cache_lookup` 里已做）。

### 4.3 RRF 融合

```python
rrf = defaultdict(float)
for rank, (cid, _) in enumerate(vec_hits, start=1):  rrf[cid] += 1 / (60 + rank)
for rank, (cid, _) in enumerate(kw_hits,  start=1):  rrf[cid] += 1 / (60 + rank)
ordered = sorted(rrf.items(), key=lambda x: -x[1])[:limit]
```

- 只用**名次**：1/(60+1)=0.0164，第 10 名 0.0143，区分度平滑；
- 两路都命中的切片分数叠加 → 天然优先；
- `RRF_K=60` 是经验值（原论文 60），可用 `config.RRF_K` 调。

### 4.4 切片重叠

```python
tail, tail_len = [], 0
for p in reversed(cur):
    if tail_len + len(p["text"]) > overlap_chars and tail:
        break
    tail.insert(0, p); tail_len += len(p["text"])
cur, cur_len = tail, tail_len
```

- 重叠单位是**块**而非字符，避免把句子切碎；
- 若第一块就超过 `overlap_chars`，`tail` 为空时仍保留一块（`and tail` 的作用），否则下一片会从空开始丢上下文。

### 4.5 PDF 解析：对象扫描 + ToUnicode

关键三步：

1. `_scan_objects`：按对象边界扫描，`stream` 只在字典闭合后识别，避免把后续对象吞进来；
2. `_expand_objstm`：解压对象流，把压缩对象还原到 `objects` 字典；
3. `extract_page_text`：按 `Tf` 切字体、`Tj/TJ` 解字符串、`Td/Tm/T*` 断行，用字体 ToUnicode 还原中文。

```python
token_re = re.compile(
    rb"/([A-Za-z0-9#_.+-]+)\s+[\d.]+\s+Tf|"
    rb"(\((?:\\.|[^\\()])*\)|<[0-9A-Fa-f\s]+>)\s*Tj|"
    rb"\[((?:\((?:\\.|[^\\()])*\)|<[0-9A-Fa-f\s]+>|[^\]])*)\]\s*TJ|"
    ...)
```

> 坑：`TJ` 数组里的大负数 kerning（如 `-250`）往往是**词间空格**，不处理会导致中文粘连。

### 4.7 聚类：并查集 vs 贪心

```python
parent = list(range(n))
for i in range(n):
    for j in range(i + 1, n):
        if sim(items[i], items[j]) >= threshold:
            union(i, j)
groups = {}
for idx in range(n):
    groups.setdefault(find(idx), []).append(items[idx])
```

- 贪心「与簇代表比较」：**依赖遍历顺序**，实测同一份数据会给出 47 / 38+10 两种结果；
- 并查集连通分量：结果唯一，且单链能跨过「中间问法」把同义句连起来；
- 代价 O(n²)，先按 norm 去重把 n 压到 66，实测量级毫秒。

### 4.8 抽取式兜底：不编造

```python
picks = [(score(s, q_terms), s, idx) for 每片每句]
picks = [p for p in picks if p[0] > 0]                 # 与问题无词重叠的句子直接丢
best = max(p[0] for p in picks)
picks = [p for p in picks if p[0] >= best * 0.45]      # 只留与最佳句同档的
```

- 过滤条件：跳过章节标题、设问句（以 `？` 结尾）、与提问重复的句子、过短文本；
- 输出「结论 + 关键要点」并带 `[n]`，与远程模型的结构对齐，前端无需分支渲染；
- 明确标注「本地检索增强引擎」，避免误导。

### 4.9 SSE 服务端

```python

```

```python
self.send_header("Cache-Control", "no-cache, no-transform")
self.send_header("Connection", "close")
self.send_header("X-Accel-Buffering", "no")
...

```

- `HTTP/1.1` 下不设 `Content-Length`，靠 `Connection: close` 结束；
- `BrokenPipeError` 必须吞掉（用户关页面会断流）；
- 生成器里任何异常都要转成 `event: error` 帧，否则前端一直等待。

### 4.10 分发与鉴权

```python
for method, pattern, fn, perm in ROUTES:
    m = pattern.match(req.path)
    if m:
        allowed_methods.add(method)
        if method != req.method:
            continue
        req.params = m.groupdict()
        try:
            if perm:                     # ← 路由级权限在此统一执行
                _require(req, perm)
            return fn(req)
        except ApiError as exc:
            return fail(str(exc), exc.status, exc.code)
```

- 路由表是「元数据」：路径、正则、处理器、权限一次声明；
- 处理器内部仍可调用 `_require(req, "更细权限")` 做二次判断（如 `kb:perm`）；
- 405 与 404 都要区分：路径存在但方法不对 → 405。

## 五、知识点总表

### 5.1 鉴权与安全

1. 认证（你是谁）与授权（你能干什么）分离；
2. RBAC：用户 → 角色 → 权限，权限分「菜单」与「操作」；

6. 越权提示的「最小信息」原则（只报数量，不报标题）；
7. 管理接口双重防护：前端隐藏 + 后端强制；
8. 密码用慢哈希 + 盐；JWT 有期限；密钥不落代码；

11. 文档 → 片段 → 向量 → 召回 → 重排 → 上下文；

14. 中文检索用二元组，避免分词依赖；

## 七、设计权衡问答

**Q1：为什么鉴权不写进召回 SQL？**
A：写进 SQL 更「快」，但拿不到被拦截清单，无法满足「部分参考资料因权限受限无法展示」的需求；本项目的做法是召回后过滤并保留 `denied_ku`，同时把拦截写入审计。

**Q2：为什么不用 LangChain / LlamaIndex？**
A：课程项目要演示「链路可解释」。自研的每一步（召回、鉴权、Prompt、引用、日志）都能单独展示与测试；框架会把关键逻辑藏起来，答辩时反而说不清。

**Q3：480 token 是不是太小？**
A：对「制度条文」类文档合适：一片通常 2~5 个自然段，既完整又能定位。若文档很长（合同、年报），可保持 480 并让切片自然增多；若问答非常细碎，可降到 320 提升精度。

**Q4：为什么默认本地哈希向量，而不是直接 BGE-M3？**
A：交付要「零依赖、离线可跑」。本地向量解决 80% 的原句召回；BGE-M3 作为可插拔增强，接上后改述召回从 7/9 提升到 8/9（Top3 8/9→9/9）。

**Q5：为什么阈值有三套？**
A：相似度的「绝对数值」依赖向量空间：本地哈希空间里相关句子只有 0.1~0.3，BGE-M3 空间里能到 0.6~0.75。阈值必须跟着引擎走，否则要么全不命中，要么全命中。

**Q6：为什么 FAQ 缓存放在检索之前？**
A：缓存的目标就是「不检索、不调模型」。放在检索之后，省下的只是 LLM 调用，向量检索和鉴权成本还在。

**Q7：为什么不直接把整篇文档喂给模型？**
A：成本、时延、注意力稀释；更重要的是**无法做知识粒度的鉴权**——整篇文档里可能混合了有权与无权段落。

**Q8：为什么用 SQLite 而不是 PostgreSQL？**
A：课程演示要「双击即跑」。SQLite 支持 WAL、事务、索引，30 篇文档性能足够；`db.py` 是唯一的数据访问层，换 PG 只需改这一层。

**Q9：多轮上下文为什么只取 4 条？**
A：制度问答的追问通常只需上一两轮；取太多会引入无关历史、冲淡当前问题。`build_messages` 取最近 4 条消息。

**Q10：为什么本地兜底引擎要输出「结论/要点/引用」结构？**
A：让前端渲染逻辑与远程模型一致，降级时用户感知最小；同时结构本身也强制「先给结论、再给依据」的表达规范。

## 九、答辩提纲

### 3 分钟版（讲清「是什么 + 亮点 + 证据」）

1. **一句话**：企业知识库，文档能进、权限能管、AI 能答、越权能拦、答完能沉淀；
2. **两条主线**：导入链路（解析→切片→向量化→入库）、问答链路（缓存→召回→**鉴权**→生成→引用）；
3. **一个亮点**：四维权限（全局/部门/角色/个人，OR 语义，默认拒绝），鉴权在 Prompt 之前，提示只报数量；
4. **一个闭环**：FAQ 聚类 → 审核发布 → 缓存秒回；未命中 → 缺口 → 补文档；
5. **证据**：双账号对比（zhangsan 被拦 / chenjing 正常）、31 个测试、BGE-M3 改述召回 7/9→8/9。

### 6 分钟版（按 README 演示脚本走）

登录权限 → 导入切片 → 配权限 → 普通用户被拦 → 管理层正常 → 聚类发布秒回 → 缺口转任务 → 看板收尾。

### 可能被追问的问题

- 「权限过滤在前端还是后端？」→ 后端，召回后 Prompt 前，有单测覆盖；
- 「召回命中但无权怎么处理？」→ 只回权限提示，不泄露标题，同时写审计；
- 「为什么不用向量数据库？」→ 30 篇/57 片，进程内暴力检索足够；接口层已隔离，可换 pgvector；
- 「模型说错了怎么办？」→ 引用溯源 + 拒答规则 + 覆盖率指标，可定位到具体切片；
- 「阈值怎么定的？」→ 本地/语义两套预设，语义档经 66 条提问实测标定。
